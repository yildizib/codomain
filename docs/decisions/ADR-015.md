# ADR-015: Use agent-mediated explicit confirmation for site actions

Status: Accepted

Date: 2026-09-17

### Context

Codomain requires human approval of reviewed content while routing all site
operations through MCP. Requiring the user to return to Dashboard would break the
selected MCP-only site-operation journey.

### Decision drivers

- Keep preview, approval, publication, and rollback inside the AI-client journey.
- Bind confirmation to exact content and action.
- Prevent replay and stale approval.
- Avoid treating API-key possession or a boolean field as human proof.

### Considered options

- Require a Dashboard session confirmation.
- Trust any authenticated MCP request as human-approved.
- Trust a client-supplied confirmation boolean.
- Use an agent-mediated, server-verifiable challenge bound to the action.

### Decision

V1 uses agent-mediated explicit confirmation. A supported MCP client presents the
preview identity, exact artifact digest or safe fingerprint, and requested action
to the user and asks for an explicit response. Codomain issues and verifies a
short-lived, single-use challenge bound to the account, initiating identity,
artifact or version, and action.

Dashboard/session confirmation is not required. Possession of an API key or a
bare `confirmed=true` value is insufficient. Expired, replayed, mismatched,
revoked-credential, suspended-account, and stale-state challenges are rejected.

### Consequences

- Supported clients must be able to pause and surface a clear confirmation step.
- Approval, publication, and rollback contracts include challenge issuance and
  completion behavior.
- Audit records distinguish API-key authentication from explicit confirmation.
- The mechanism provides the selected product-level human confirmation; it is
  not identity proof independent of the trusted client interaction.

### Revisit when

- MCP standardizes a stronger interoperable human-elicitation proof.
- Regulated or multi-user approvals require independent authentication.
- Supported clients cannot reliably implement the confirmation journey.
