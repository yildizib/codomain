# ADR-011: Route all site operations through MCP

Status: Accepted

Date: 2026-09-10

### Context

The earlier baseline used Dashboard for publication approval and rollback. The
user selected an account-only Dashboard and MCP as the entry point for the entire
site lifecycle. Runtime implementation has not started.

### Decision drivers

- Keep account administration separate from site operations.
- Provide one MCP workflow for upload, preview, approval, publication and rollback.
- Preserve artifact-bound approval, tenant isolation and auditable operations.

### Considered options

- Retain Dashboard approval and rollback.
- Offer the same site operations in both Dashboard and MCP.
- Route all site operations through MCP and keep Dashboard account-only.

### Decision

Select the third option. Dashboard uses Spring Boot MVC for registration,
sessions, account details, password changes, API key lifecycle and connection
instructions. It does not initiate site operations. MCP Server accepts upload,
deployment, preview creation/renewal, approval, publication, rollback and version
management requests. Archive semantics remain under evaluation. Worker executes
accepted operations.

This record supersedes ADR-004's prohibition on MCP publication and its
Dashboard approval boundary. The remaining separation of submission, exact-digest
approval and publication is preserved. It also refines ADR-007's interaction
boundary and ADR-010's Dashboard preview-launch description: previews are created
through MCP, with unchanged content-origin isolation, expiry and revocation.
ADR-003's API key authorization remains applicable, now to publication operations.

Approval must identify the exact sealed digest; publication and rollback have
separate durable records. The API key identifies an account and key, not proof
of an independently confirmed human decision. Explicit human approval remains a
requirement. [ADR-015](ADR-015.md) selects the agent-mediated challenge mechanism
without restoring a Dashboard approval step or authorizing silent autonomous
publication.

### Consequences

- MCP contracts add approval, publication and rollback capabilities.
- User-facing documentation must not promise Dashboard site controls.
- Audit records distinguish authenticated client identity from human confirmation.
- The old ADR text remains historical; this record controls conflicting routing.

### Revisit when

- The human confirmation/delegation policy is selected.
- Team approvals or multiple credential scopes become requirements.
