# ADR-013: Store validated artifacts on NFS and serve through separate Nginx

Status: Accepted

Date: 2026-09-10

### Context

The user wants large uploads through MCP, isolated malware checks, temporary
previews and permanent versions stored as files rather than database blobs.

### Decision drivers

- Keep DB metadata and filesystem content responsibilities clear.
- Prevent unvalidated uploads from reaching public delivery.
- Preserve approved content and support rollback without rebuilding it.

### Considered options

- Serve upload directories immediately.
- Require object storage for immutable artifacts.
- Use quarantined uploads, sealed NFS directories and separate read-only Nginx.

### Decision

Select NFS-backed file storage with PostgreSQL metadata. MCP owns upload sessions
and controlled large-file transfer endpoints. Worker validates frozen input,
runs isolated scanning and seals artifacts before preview. [ADR-016](ADR-016.md)
selects portable ClamAV integration; numeric limits, signature freshness and
transfer protocol still require selection before implementation. Incomplete
scans never authorize preview.

Nginx runs on a separate VPS, mounts only sealed content read-only and does not
mount quarantine. Applications operate on configured POSIX paths; an operator
may provide those paths through ordinary mounts without application-level NFS
integration. Private export permissions and worker write restrictions must
protect sealed content. Content origins remain isolated from Dashboard under
ADR-007 and ADR-010. Artifact mounts are not the PostgreSQL data directory.

Version records preserve the exact approved digest and may reference the same
sealed artifact used for preview without copying it. Retain approved versions
without automatic deletion and keep the last 10 temporary deployment contents.
This resolves ADR-005's permanent-version retention direction; proposed per-site,
completed-unversioned scope and quarantine expiry still need confirmation.
Cleanup must never remove active or version-referenced content.

Archive remains under evaluation. Reversible list hiding without deletion is the
proposal; cold storage and savings are not promised.

### Consequences

- Manifest hashes prove content identity; storage permissions enforce immutability.
- Filesystem preparation and DB commit require recovery, not a fictional shared
  transaction. Cleanup must coordinate with version creation.
- Live routing remains unresolved between DB resolution and a local edge pointer.
  A DB update and filesystem/edge change are not one atomic transaction. Select
  outage, cache and applied-state behavior before implementing publication.
- Versions require backup and tested restore; NFS alone is not a backup or HA plan.
- Antivirus does not replace origin isolation, abuse handling or takedown.

### Revisit when

- Routing/availability or storage retention details are finalized.
- Storage cost, scale or disaster recovery require another artifact backend.
