# Agent Instructions

Write all repository content in English. Preserve unrelated user work.

## Read before acting

| Task | Required guidance |
| --- | --- |
| Any change | [Contributing](CONTRIBUTING.md) |
| Code, tests, configuration, scripts, generated output | [Coding standards](CODING_STANDARDS.md) |
| Scope, user journeys, acceptance | [Product requirements](PRODUCT_REQUIREMENTS.md) |
| Ownership, storage, deployment, preview, publishing, rollback | [Architecture](ARCHITECTURE.md), [decisions](DECISIONS.md), [security](SECURITY.md) |
| MCP tools or integration | [MCP design](MCP_DESIGN.md), [security](SECURITY.md) |
| Authentication, credentials, uploads, URLs, authorization | [Security](SECURITY.md) |
| Product explanation | [README](README.md) |

Each document owns its subject. Correct summaries to match the authoritative
source; never silently weaken requirements or expand V1. Use architecture
terminology and record significant decisions as described in Decisions.

## OpenSpec workflow

- Use the repository's OpenSpec configuration for product and architecture
  changes.
- Read the relevant OpenSpec artifacts before implementing a planned change.
- Keep implementation aligned with the approved proposal, design, specs, and
  tasks. Surface scope or design conflicts instead of silently narrowing them.
- Validate the relevant OpenSpec artifacts after changes.
